# iCare 현재 상태

2026-09-19 최신: 사용자 승인으로 회원가입 변경 `881d163`을 main에 병합했다. 후속 `feat/rag-service`에서 채팅·일과표 검색 연결과 실제 지식 등록/검수를 진행했다. 원격 push/DNS/외부 배포는 하지 않았다.

## 검색 기반 상담과 일과표

- 사용자 승인한 공식 출처의 한국어 비공식 요약 5개를 기존 실제 DB에 등록했다. 버전 5개·3072차원 임베딩 5개이며 기존 계정·일지·대화 등 15개 테이블은 보존했다. 등록 전후 백업 모두 격리 복원·비교했다.
- 채팅과 일과표 모두 Spring AI/Gemini/pgvector 검색을 사용한다. LangChain으로 교체하지 않았다. 출처·지역·월령을 표시하며 근거 없는 생성과 잘못된 출처 번호는 근거 부족 안내로 처리한다.
- 일과표는 분석 날짜의 월령과 기록된 항목을 사용한다. 미기록을 0회/정상으로 해석하지 않는다. 수유·배변용으로 검토한 2개 출처만 검색하여 무관한 발달·수면 권고 혼합을 줄였다. 출처 목록은 `.env`의 ICARE_DAILYLOG_SOURCE_URLS에 있다.
- 실제 무료 Gemini로 합성 질문을 검사했고 첫 답변에서 발견한 월령 혼합 문제를 수정·재검수했다. 화면 검수는 합성 API로 별도 진행했다. 모든 질문의 의료 정확성이나 공개 서비스 준비 완료를 뜻하지 않는다.
- 등록 내용/검증/복구/실행은 [RAG 서비스 검수](RAG_SERVICE_RUNBOOK.md)를 따른다. 사용자 승인으로 RAG 커밋 `35ce3c6`을 main에 fast-forward 병합했다. 실제 Naver Cloud 구매·배포는 아직 실행하지 않았다.

## 회원가입 후속 변경

- 공식 카카오 우편번호 SDK의 화면 내 주소 검색과 상세주소 입력을 추가했다. 팝업 차단을 피하고 모바일에서도 화면 안에서 선택한다. 우편번호·기본주소·상세주소를 별도로 서버에 보내고 서버가 검증 후 기존 address 필드에 합쳐 저장한다. DB 스키마는 변경하지 않는다. 검색 서비스 로딩 실패 시 안내하고 직접 주소 입력도 유지한다.
- 비밀번호 최소 10자/UTF-8 최대 72바이트로 서버 정책과 가입·비밀번호 변경 화면을 맞췄다. 가입 시 비밀번호 확인은 화면에서만 비교하고 서버로 전송하지 않는다. 두 값이 다르면 다음 단계와 가입 요청을 차단한다.
- 계정 정책 단위 테스트 6개(10자 가입, 9자 거절, 72바이트 경계 등), Next.js production 빌드·타입 검사 통과. 수정 파일 lint 오류 0/마이페이지 기존 경고 1이다. 실제 DB 쓰기·가입메일 발송 없이 확인했으며 백엔드를 재시작했다.
- 사용자 승인으로 별도 Chrome/Playwright에서 UI 검수 9개 통과: 9자 차단, 확인값 불일치, UTF-8 상한, 실제 공개 주소 검색·선택·기존 상세주소 초기화, 10자 다음 단계, 이전 단계 주소 유지와 가입 payload, JS 오류 없음, 375px 모바일 검색/다시 열기/닫기/가로 넘침 없음, SDK 로딩 실패 시 직접 입력. 로컬 가입·메일 API는 가로채 테스트 응답으로 대체했으며 실제 계정 생성이나 발송 성공으로 해석하지 않는다. 기존 프론트 Node 테스트 10개도 통과했다.
- Codex 내장 브라우저에서는 주소 검색 미표시/날짜 입력 중 탭 종료가 관찰되어 일반 Chrome 검수로 전환했다. 이 내장 브라우저의 호환성까지 해결된 것으로 표현하지 않는다.
- 이후 사용자 승인으로 회원가입 브랜치를 main에 병합했다(`881d163`).

### 로그인 화면 오류·주소 필수 검증 후속 수정

- 로그인 상태가 서버/브라우저 첫 렌더에서 달라 발생한 홈 hydration 오류를 수정했다. 서버 스냅샷을 일치시키고 같은 화면 로그아웃 및 토큰 만료도 반영한다. 로그인 화면의 잘못된 /register 링크를 /signup으로 수정했다.
- 주소 검색 선택 시 우편번호도 채운다. 우편번호 5자리, 기본주소, 상세주소를 모두 필수로 검사한다. 검색 실패 시 수동 입력에도 같은 기준을 적용한다. 서버는 누락·공백·주소 총 255자 초과를 DB 접근 전에 거절한다. 이름·닉네임·전화번호·생년월일·아기 정보도 서버에서 검증한다. 기존 계정의 주소를 수정하거나 DB 스키마를 바꾸지 않는다.
- 비밀번호는 기존 BCrypt 저장을 유지한다. 실제 DB 읽기 전용 집계에서 일반 계정 모두 BCrypt 형식이고 다른 형식은 0건이었다. 해시값·이메일은 출력/문서화하지 않았다. 새 가입의 해시·salt, 평문과 불일치, 응답에서 해시 제외, 이메일 인증 전 로그인 거절, 잘못된 비밀번호 거절, 인증 후 로그인, 비밀번호 변경 후 기존 비밀번호 거절을 테스트했다.
- 최종 백엔드 테스트 48개 통과/15개 환경 선택 검사 제외/실패 0. 이 중 가입·보안 관련 22개 통과. Chrome 가입 UI 10개와 로그인 실패/성공·로그인 상태 새로고침·로그아웃·토큰 만료 검수 통과. 실제 공개 건물 주소 검색(PC/375px 모바일), 우편번호·기본주소·상세주소 누락, 상세주소 공백, SDK 로딩 실패와 직접 입력을 확인했다. 모바일 검색 화면도 시각 검수했다.
- 프론트 Node 테스트 10개, 변경 파일 lint(오류·경고 0), Next.js production 빌드(Turbopack)·타입 검사 통과. Node 22.17에서는 --experimental-strip-types 옵션으로 테스트한다.
- 백엔드 재시작 후 readiness 200/가입 화면 200, 실제 로컬 프록시→백엔드 경로에서도 상세주소가 없는 합성 가입 요청이 400으로 거절됨을 확인했다. 실제 신규 계정 생성·메일 발송은 하지 않았다. Codex 내장 브라우저의 외부 검색 미표시는 일반 Chrome 검수와 구분하며 해결됐다고 주장하지 않는다.
- feat/signup-improvements에서 수정 후 사용자 승인으로 main에 병합했다(`881d163`).

## 현재 실행과 변경

- Docker에는 기존 PostgreSQL과 Redis만 상시 실행하며 둘 다 loopback에만 포트를 연다. DB 원본·기존 볼륨·백업을 보존했다. 임시 검증 앱/DB/프록시는 정리했다.
- 로컬 프론트와 백엔드는 PC에서 직접 실행한다. 모든 서버 민감값은 Git에서 제외한 루트 .env로 통합했다. 공개 지도 JavaScript 키는 브라우저에서 보이는 용도다.
- 일반 이메일로 회원가입할 수 있다. 이메일 인증, 관리자 역할 분리, 사용자/가족 권한, 서버 프록시 인증은 유지한다. 고정 이메일 제한은 제거했다.
- 게시글 목록은 Redis 30초 캐시를 사용하고 변경 커밋 후 무효화한다. AI/인증 횟수와 AI 중복 요청 제어를 Redis로 공유한다. 채팅·게시글·아기 정보 원본은 PostgreSQL이다.
- 기존 Flyway V1~V3/3072차원 임베딩/최근 대화·아이 범위/문서 검토·버전·출처 기능을 유지한다. 이번 후속 작업에서는 실제 DB를 변경하지 않았다.
- 향후 집 PC Docker 배포용 blue/green 구성, 준비 상태 검사, Nginx 전환·복구, CI/수동 배포 워크플로를 준비했다. DB 자동 변경은 검수한 이력/파일 해시 검사로 차단한다.

## 검증과 한계

백엔드 35개 통과/선택 DB 검사 11개 제외, Redis 단계 호스트 API 48개, 프론트 Node 10개, JAR/Next standalone 빌드·타입 검사 통과. 전체 프론트 lint는 오류 0/기존 경고 9다. 실제 Nginx와 합성 호스트 서버로 전환·진행 중 요청 유지·정적 파일·실패 복구를 검증했다. 최종 호스트 백엔드의 DB 장애 시 readiness 503/liveness 200도 확인했다.

실제 가입메일, Spring AI를 통한 실제 사용자 상담 전체 흐름, 실제 Docker 앱 이미지와 blue/green 전체 배포, GitHub CI 실행/runner 설정, 외부 도메인 연결은 아직 검증하지 않았다. 기존 합성 Gemini REST 연결 성공을 전체 앱 검증으로 대신하지 않는다. 기존 원본 파일 CRC 오류를 복구한 것으로 표현하지 않는다.

## 지금 로컬 테스트

```powershell
./scripts/Start-IcareLocal.ps1 -Service backend
./scripts/Start-IcareLocal.ps1 -Service frontend -Webpack
```

현재 실제 .env로 프론트·백엔드를 이미 호스트에서 실행 중이다. readiness/가입 화면/인증 경계 검사도 통과했다. 주소: http://127.0.0.1:3000. 사용자가 SMTP 설정을 입력한 뒤 Gmail TLS 연결·로그인 성공을 확인하고 백엔드를 재시작했다. 재시작 후 readiness/가입 화면은 200이다. 메일은 보내지 않았으므로 실제 가입 인증메일 수신·인증 완료는 여전히 미검증이다. 지도 REST 키도 기존 설정을 이전했으므로 실제 호출 확인이 남아 있다. 실제 관리자 초기 생성은 별도 설정/검수 후 진행한다.

상세 변경·복구: [로컬 실행](LOCAL_RUNTIME_RUNBOOK.md), [Redis](REDIS_RUNBOOK.md), [배포 준비](DEPLOYMENT_RUNBOOK.md). 실제 DB 복구는 [Flyway](FLYWAY_RUNBOOK.md), 최신 지식 등록과 검수는 [RAG 서비스](RAG_SERVICE_RUNBOOK.md)를 따른다. 공식 원본은 로컬 doc에 보관했고 승인한 짧은 요약만 등록했다. DOCX 작성은 미수행이다.

현재 실행 중인 로컬 앱 종료: ./scripts/Stop-IcareLocal.ps1. Docker DB/Redis는 유지한다. 재시작은 위 실행 명령을 별도 터미널에서 사용한다. 환경변수를 바꿨으면 앱을 재시작한다.
