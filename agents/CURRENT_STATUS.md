# iCare 현재 상태

2026-09-19 환경설정 병합 후 기준. 핵심 리팩토링과 DB 전환은 마쳤지만 부부의 실제 사용 전 과정이 검증된 상태는 아니다. 로컬 main에 환경설정 129b106까지 병합했고 원격 push/배포는 하지 않았다. 실행 중인 Docker 컨테이너는 실제 PostgreSQL 하나(healthy)이며 실제 웹앱/백엔드는 시작하지 않았다.

프레임워크는 Next.js + Spring Boot + Spring AI 그대로다. LangGraph나 로컬 AI로 교체하지 않았다. 원래 D: 파일의 CRC 오류를 복구한 것이 아니라 사용자가 승인한 새 서비스 DB를 구성하고 이후 데이터를 보존한 것이다.

## 현재 코드의 요청 흐름

로컬에서는 브라우저 → Next 서버의 /api → 서비스 인증이 붙은 백엔드 요청 → 사용자/가족 권한 검사 → DB/Gemini 순서다. 외부 목표 구조에서는 Next 서버(Vercel)와 집 PC 사이에 Cloudflare Tunnel·Access를 넣는다. 이 외부 연결은 아직 구성·실연결 검증 전이다. DB와 원본 서비스 인증값을 브라우저에 공개하지 않는다.

상담 질문은 상담방 권한과 선택 아이의 현재 가족 권한을 확인한 뒤, 제한된 최근 대화/아이 프로필/검색된 현재 문서 발췌/현재 질문을 함께 모델에 전달한다. 성공한 질문·답변과 실제로 전달한 참고자료를 저장한다. 문서가 등록되지 않았거나 검색 결과가 없으면 자료 근거가 있는 것처럼 표시하지 않는다. 실제 지식 문서는 아직 등록하지 않았다.

문서 등록은 관리자 미리보기 → 추출·출처 확인 → 신규 등록 또는 교체 승인 → 임베딩/버전 저장 순서다. 기존 버전은 삭제하지 않고 새 검색에서 제외한다. 이 기능의 구현·합성 검증과 실제 의료 자료의 검토·등록은 별개다.

## 검증 범위

최신 환경설정 단계에서 일반 JUnit 27개, 프론트 Node 9개, 격리 Docker HTTP 48개와 이미지 빌드/시작 검사가 통과했다. 앞선 단계에서 V3 마이그레이션·백업 복원·기존 데이터와 벡터 보존을 별도 검증했다. 실제 새 키로 합성 REST 답변 및 3072차원 임베딩을 확인했다. 이는 실제 Spring AI 앱에서 두 사용자가 가입하고 상담/검색하는 전체 흐름의 검증을 대신하지 않는다.

기존 frontend 전체 lint 오류 6개/경고 10개는 남아 있다. 변경 파일 검사와 빌드 통과를 전체 코드 검사의 통과로 표현하지 않는다.

## 실사용 전 남은 작업

1. SMTP 계정/앱 비밀번호 설정 및 실제 가입·이메일 인증. 현재 허용 이메일은 사용자 요청대로 한 개이며 부부 테스트 전에 두 번째 주소를 추가한다.
2. 실제 앱을 로컬로 실행하고 가족 합류, 아이 선택, 대화 맥락, 일지 접근 제한, API 실패·한도 상황을 확인한다. 실제 관리자 초기 설정은 별도 검수 후 진행한다.
3. 공식 자료 수집·DOCX 작성은 별도 요청으로 진행하고 내용 승인 후 지식 등록·검색·답변 출처를 확인한다. 현재 실제 지식 테이블은 등록 전이다.
4. Cloudflare Tunnel/Access와 Vercel의 외부 연결 준비/실연결 검증. DNS 변경·Vercel 배포는 현재 합의 범위 밖이며 별도 승인 대상이다.
5. 남아 있는 기존 frontend lint 오류를 필요한 범위에서 정리한다.

실행 방법과 복구는 [환경설정 작업서](ENVIRONMENT_RUNBOOK.md), DB/문서 버전 주의사항은 [문서 검색 작업서](KNOWLEDGE_RUNBOOK.md)를 따른다.
