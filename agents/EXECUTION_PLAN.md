# iCare 비공개 테스트 준비: 실행 합의

결정 기준: 2026-09-08 사용자 지시. 이 문서는 작업 범위와 승인 기준이며 구현 완료 보고가 아니다.

## 목표와 범위

부부 두 명이 육아 챗봇과 육아 일지를 비공개 테스트한다. 기존 Next.js + Spring Boot + Spring AI + Gemini와 집 PC Docker PostgreSQL/pgvector 데이터를 유지한다. 집 PC의 실제 상태는 작업 시 재확인한다.

목표 연결은 브라우저 → Vercel 서버 측 `/api` 전달 → Cloudflare Tunnel·Access → 집 PC 백엔드 → 기존 DB·Gemini API다. Tunnel은 연결 통로이고 실행 서버는 집 PC다. 서비스 인증값은 Vercel 서버에서만 사용하며 브라우저에 노출하지 않는다. DB는 인터넷에 공개하지 않는다.

2단계에서 Next.js 서버 전달 경로와 서비스 인증을 구현했으며 Cloudflare/Vercel 실제 연결·배포는 아직 하지 않았다. 목표 구조를 현재 배포 상태로 표현하지 않는다. Vercel·Cloudflare 제약, Gemini 모델/API 결제·설정은 실제 연결 시 다시 검증한다. Google AI Pro 구독을 API 결제 확인으로 대신하지 않는다.

가비아 도메인 등록은 유지한다. 향후 DNS 관리 변경이 필요하면 Vercel·메일 등 기존 기록 보존 절차를 준비한다. 이번 리팩토링에서는 실제 DNS 변경이나 Vercel 배포를 하지 않는다.

## 작업 방식과 승인

2026-09-19 후속 범위: 사용자가 Gemini 키를 발급해 루트 .env에 입력하고 JWT/API/CORS 등의 .env 관리를 요청했다. 제안한 feat/env-config에서 설정 연결과 합성 API 확인을 진행한다. DB 마이그레이션 추가/결제 활성화/외부 배포는 포함하지 않으며 main 병합은 변경·검증 결과 제시 후 별도 검수받는다.

- 단일 에이전트가 순차 진행한다. 희망 실행 설정은 Astra High, Fast 끔이며 실제 설정 확인 없이 적용했다고 보고하지 않는다.
- 일반 코드 수정은 매번 승인받지 않는다. 각 단계에서 빌드·실행 가능 상태와 필요한 검증을 유지하고 불필요한 반복 검사·UI 개편·전체 재설계를 피한다.
- 기존 미커밋 변경을 보존한다. `reset`, 강제 checkout, 임의 stash·삭제로 정리하지 않는다.
- 2026-09-08 승인된 브랜치 구성: `feat/architecture-docs` → `feat/flyway-baseline` → `feat/private-backend`. 각 기능의 검증 결과를 제시하고 병합은 별도 승인받는다. 3·4단계 브랜치 구성은 착수 전에 검수받는다.
- 기본 병합 대상안은 `main`이며 실제 병합 요청 시 대상과 커밋·변경 내용을 명시한다. 다음 기능은 승인된 병합 결과에서 분기한다.
- 후속 사용자 승인으로 2단계 52245b7을 main에 병합하고 `feat/chat-context`에서 3단계를 진행했다. 2026-09-13 재검수·진행 요청에 따라 3단계 adf45c8을 main에 병합하고 실제 V2를 적용했다. 승인된 `feat/knowledge-ingestion`에서 4단계를 구현했다. 9월 19일 최종 격리 검증 후 사용자 승인으로 edffb57을 main에 병합하고 실제 V3를 적용했다. 적용 전후 새 백업의 격리 복원·보존 검증을 완료했다.
- 실제 DB 적용은 검증 결과, 실행 SQL, 백업 위치·복구 절차를 보여준 뒤 승인받는다. 승인 대기 중 독립 코드 작업은 가능하되 브랜치 검수 조건도 지킨다.
- 실제 지식 데이터 삭제·교체는 별도 승인 대상이다. 기존 계정 데이터는 삭제하지 않는다.

## 단계와 완료 조건

### 0단계: 아키텍처와 작업 지침

현재 구조·핵심 요청 흐름·초기화 부작용을 소스에서 재확인한다. 기존 분석 문서와 새 실행 합의를 연결하고 영역별 AGENTS.md로 지침을 구성한다. 여러 에이전트를 실행한다는 뜻이 아니다. 현황과 미검증을 기록하고 문서 변경을 검수받는다.

### 1단계: 데이터 보존과 Flyway

진행 중 원본 파일의 CRC 오류가 확인된 뒤 사용자는 새 DB 실행을 시도하고 데이터가 거의 없으므로 Flyway 작업을 계속하도록 요청했다. 확인된 새 볼륨은 초기화되지 않은 빈 상태다. 현재는 빈 DB용 V1과 합성 데이터의 baseline/복원 검증을 준비하며, 기존 원본을 복구한 것으로 간주하지 않는다. 원본 파일은 보존한다. 최신 결과와 실제 적용 승인 범위는 [Flyway 작업서](FLYWAY_RUNBOOK.md)를 따른다.

1. 실제 컨테이너, 이미지, 마운트/볼륨, 네트워크, 포트, DB 버전을 조회한다. 루트 Compose로 서비스 DB를 새로 만들지 않는다.
2. 백업은 Git 밖에 보관한다. 백업 성공·크기·해시·복원 가능성을 확인하고 격리 DB에 복원한다. 원본 데이터의 내용을 문서로 출력하지 않는다.
3. 실제 스키마와 14개 JPA 엔티티의 컬럼·타입·NULL·키·기본값·시퀀스를 비교한다. 벡터 테이블, 확장, 인덱스, 차원, 기존 임베딩 모델·문서도 별도로 확인한다. 모델을 확인할 수 없으면 차원만으로 추정하지 않는다.
4. `db/migration`에 초기 마이그레이션을 작성한다. 빈 DB 최초 구성과 복원 DB의 명시적 baseline을 각각 검증한다. 불일치를 해결하기 전 baseline을 찍지 않는다.
5. 전환 후 `ddl-auto=validate`, Spring AI 자동 스키마 생성 끔, `baseline-on-migrate=false`, Flyway clean 비활성화를 적용한다. 초기화 runner가 검증 중 실제 계정·설정·문서를 바꾸지 않도록 격리한다.
6. 테이블별 행 수·필요한 데이터 무결성·시퀀스·벡터 보존과 Hibernate 검증 결과, 최종 SQL, 원본 복구 절차를 제시한다. 실제 DB 적용은 별도 승인 후 수행한다.

서비스 DB 중복 생성은 금지하고 검증용 DB만 격리 생성한다. 백업 파일 존재만으로 복구 검증을 통과했다고 하지 않는다. 운영 적용 전후 쓰기 중지 범위와 새 기록 유실 방지까지 복구안에 포함한다.

### 2단계: 실행과 비공개 접근

2026-09-08 후속 요청으로 우선 한 이메일만 등록하고 두 번째 주소를 추가할 위치를 주석으로 남겼다. 설정은 1~2개를 허용하며 비어 있으면 모두 차단한다. 실제 주소는 소스·문서에 기록하지 않는다.

기존 DB에 연결하는 재현 가능한 백엔드 Docker 빌드·실행 설정, 비밀값 환경변수 분리, 안전한 관리자 초기 설정을 준비한다. 고정 기본 관리자 비밀번호를 제거하고 기존 관리자 상태는 보존·점검한다.

허용한 두 이메일만 가입·로그인할 수 있도록 하며 실제 이메일은 보안 설정으로 받고 문서에 복사하지 않는다. 회원가입 역할 주입을 차단하고 사용자·가족·관리자 권한을 검증한다. 채팅과 건강 문진 등 AI 진입점의 입력 길이·출력 길이·호출 빈도를 제한한다.

Vercel 서버 전달 경로와 Cloudflare 서비스 인증 연결을 준비한다. 서비스 인증과 사용자 인증은 각각 검증한다. 직접 백엔드 접근·헤더 위조·다른 가족 데이터 접근 차단, 비밀값의 브라우저 번들 노출 여부를 검사한다. DNS·Vercel 변경은 실행 절차만 작성한다.

### 3단계: 예산 내 대화 맥락

최근 대화를 제한된 길이로 모델에 전달한다. 권한이 있는 아기 프로필만 참고하며 여러 아기 중 임의 선택하지 않는다. 사용자·가족 간 정보 혼합을 방지한다. 일반 채팅·건강 문진의 의사 자칭을 육아 정보 안내 AI로 수정하고 DB 프롬프트 설정도 확인한다. 저장된 설정 변경은 실제 DB 승인 원칙을 따른다.

### 4단계: 예산 내 문서 검색

PDF·DOCX 형식별 추출, 새 문서 반영, 중복 등록 방지, 문서 버전·교체와 이전 버전 검색 제외를 구현한다. 출처·개정일 메타데이터와 실제 검색 근거를 표시한다. 기존 자료의 문제는 검토 목록으로 기록하며 전체 의료 자료 조사·재작성은 하지 않는다. 스키마 변경은 새 Flyway 버전, 기존 지식 삭제·교체는 별도 승인으로 관리한다.

## 별도 작업

공식 자료 검색·주제별 DOCX 작성·자동 수집 개발은 이번 범위에 포함하지 않는다. 추후 일회성 수집은 0~12개월 수유·안전 수면·발달·예방접종·진료 필요 증상을 대상으로 국내 공식 기관·학회·WHO·AAP 공개 원문을 확인한다. 출처·날짜·대상 월령과 국내외 권고를 구분하고 문서 검토·승인 후 별도로 지식 등록·검색 출처를 검증한다.

진료용 요약 화면/PDF, 의료진 공유 링크, EMR 연동은 장기 검토다. 부모 입력 사실과 AI 요약을 구분하고 미기록을 0회·정상으로 해석하지 않는 원칙을 유지한다. 담당 소아과 의사에게 필요한 요약 항목을 먼저 확인하는 방향이다.
