# 백엔드 작업 지침

- 루트 지침과 [실행 합의](../../agents/EXECUTION_PLAN.md), [백엔드 분석](../../agents/BACKEND.md), [실행·검증](../../agents/DEVELOPMENT.md)을 먼저 읽는다.
- Spring Boot + Spring AI + Gemini 구조를 유지한다. 프레임워크 교체나 전면 패키지 이동은 현재 범위가 아니다.
- 실제 DB의 컨테이너·마운트·스키마·벡터 차원은 설정 파일만으로 확정하지 않는다. 데이터와 임베딩을 보존한다.
- 백업 및 격리 복원 검증을 완료한 후 초기 Flyway SQL을 확정한다. 빈 DB와 기존 DB의 명시적 baseline 경로를 각각 검증한다.
- 전환 후 Hibernate는 validate, Spring AI 스키마 자동 생성은 비활성화, Flyway clean은 비활성화한다. baseline-on-migrate로 기존 스키마 불일치를 우회하지 않는다.
- 기존 DB 적용 승인을 받기 전에는 해당 DB에 애플리케이션·마이그레이션·초기화 runner를 실행하지 않는다. 기존 contextLoads도 실제 DB와 외부 AI에 접근할 수 있다.
- 테스트는 실제 가족·사용자·채팅·일지 데이터의 경계를 검증한다. 다른 가족 요청은 DB 변경·CSV 출력·AI 호출 전에 차단해야 한다.
- 기존 계정과 사용하지 않는 것으로 보이는 엔티티/테이블도 임의 삭제하지 않는다. 추가 스키마 변경은 새 Flyway 버전으로 관리한다.
- 백업, 원문 사용자 데이터, 인증값을 Git·문서·테스트 fixture에 넣지 않는다. 로그와 명령 출력도 필요한 집계·메타데이터로 제한한다.
- 기능별 검증 결과, 실행·복구 방법, 미검증 항목을 agents 문서에 갱신한다. 서브에이전트는 사용하지 않는다.
